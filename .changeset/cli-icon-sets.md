[feat] Icon sets: an integration can ship an icon set. Agents find icons by meaning and get the exact import line, and copied templates use the project's icons.

- **Icon definitions.** Astryx ships a list of icon definitions, one typed `IconDefinitionDoc` file each (`name`, `description`, `words`, and `builtIn` for the shared icon names Core renders). `astryx docs icon-definitions` lists them all, plus each installed set's own, and `astryx search` finds each one. `@astryxdesign/cli/authoring` exports `IconDefinitionDoc` and `parseIconDefinition`.
- **Authoring a set.** The integration manifest's new `iconSets` field points at a folder with one folder per set. Each set has a typed `<name>.doc.mjs` (`IconSetDoc`), a `<name>.icons.json` data file, and an optional `definitions/` folder of its own definitions. The data file lists every icon's export and search words, and a `map` from each definition to the icon that draws it; optional `generated` and `adapter` fields name the set's generated icons module and a function that turns non-component library exports into components. `@astryxdesign/cli/authoring` exports `IconSetDoc`, `IconSetData`, `parseIconSet`, and `parseIconSetData`. Discovery reads every file without running the icon module, and withdraws a set whose data is invalid or whose module does not resolve.
- **Authoring commands.** `astryx integration add icon-set <name>` (and `integrationAddIconSet`) writes a new set; with `--from <module>` it wraps every component a library exports (and, once the set declares an `adapter`, every data export), leaving out a prefix every icon-like export shares (`--exclude` drops exports that are not icons), and running it again refreshes the icons and keeps the map. `astryx integration add icon-definition <name>` (and `integrationAddIconDefinition`) adds a set's own definition. `astryx icon add <Export> --from <module>` verifies the export statically and lists the definitions that fit it; `--definition` or `--new-definition` adds the icon as `<Name>Icon` through the set's generated module (with its `.d.ts` and the `themeIcons` theme map, both kept in sync) and maps it (`--default` for a default export, `--appearance`/`--size`/`--weight` for a variant). `astryx icon map <definition> <icon>` edits one map entry, and `astryx icon use <set>` writes `iconSet` to astryx.config. The API gains `iconAdd`, `iconMap`, and `iconUse`. The guide `astryx docs cli/integrations/building-blocks/icon-sets` covers every flow, how icons are exported, library shapes, and the checks.
- **`astryx icon`.** `astryx icon <words>` ranks icons across the installed sets (`icon.search`): a definition the set's `map` names the icon for first (an icon also matches the name and words of every definition it is mapped to, so the data file need not repeat them), then exact matches on the id or a word (meaning leads unless more of the searched icons are named for the query than tagged with it), then a word that starts with the query, then partial matches. `astryx icon <set>/<id>` reads one icon with every variant's import line (`icon.detail`). `astryx icon --list` lists each set with its definition coverage (`icon.list`).
- **`astryx search` and `discover`.** Search includes installed icons under the new `icon` domain (`--type icon`), below a component or doc match of equal score. `astryx discover` lists icon sets as the `icon-set` kind (`--type icon-set`), and `discover <package>/<set>` shows the set's description, license, icon count, default variant, and the definitions it covers.
- **Templates follow the project's set.** The new `iconSet` field in `astryx.config` picks the project's set; without it, the only installed set is used. Template and block descriptors gain `icons`, the definition each imported icon draws, and every bundled template declares its icons. `astryx template` (printed or copied) replaces each declared icon with the project set's icon for that definition, or an icon another installed set ships by a reviewed `exact` or `strong` match. Nothing is guessed from names; an icon with no mapping keeps its import. `template.show` and `template.copy` gain an `icons` report of each icon `mapped` or `kept`.
- **Checks.** `astryx integration check` (and `doctor integration validate`, which also type-checks `IconSetDoc`) adds icon-set codes. Errors: `invalid_icon_set`, `icon_builtin_definition_missing`, `icon_module_not_public`, `icon_not_component`, `icon_export_missing` (re-exports followed through relative files and installed packages), `icon_module_invalid`, `icon_generated_types_mismatch`, and `icon_theme_map_mismatch`. Warnings: `icon_definition_unused`, `icon_definition_shadowed`, `icon_export_name`, `icon_theme_map_unchecked`, `icon_source_version_drift`, and `icon_license_notice_missing`. Info, which never fails: `icon_definition_missing`, another Astryx definition the set does not map, so a set that maps every built-in passes `--strict`. A missing-definition finding names the definition's description and words, and suggests an icon only when one's id is the definition's name or one of its words. Text output prints a package-wide finding once, under the first check. `astryx doctor` adds an `icon-sets` check and counts a package's icon sets among what it contributes, and `integration verify` lists icon sets in its summary.
