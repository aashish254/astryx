[feat] Icon sets: an integration can ship an icon set, and agents find icons by meaning and get the exact import line.

- **Authoring.** The integration manifest's new `iconSets` field points at a folder with one folder per set. Each set has a typed `<name>.doc.mjs` (`IconSetDoc`) and a `<name>.icons.json` data file that lists every icon's export, the words people search for, and the shared icon names (`IconName`) it draws. `@astryxdesign/cli/authoring` exports `IconSetDoc`, `IconSetData`, `parseIconSet`, and `parseIconSetData`. Discovery reads the descriptor and data file without running the icon module. It withdraws a set whose data is invalid or whose module does not resolve from the project. `astryx integration add icon-set <name>` (and `integrationAddIconSet`) writes a new set: its descriptor, a starter data file with no icons, the `iconSets` root, and the root in package.json `files`. `astryx discover` lists icon sets as the `icon-set` kind (`--type icon-set`), and `discover <package>/<set>` shows the set's description, license, icon count, default variant, the shared icon names it fills, and the command that searches its icons. `doctor integration validate` type-checks each `IconSetDoc` descriptor. The new guide `astryx docs cli/integrations/building-blocks/icon-sets` covers adding a set, its data file, generating it from a library's tags, its checks, and how apps use it.
- **`astryx icon`.** `astryx icon <words>` ranks icons across the installed sets (`icon.search`): first a shared icon name the icon fills, then exact matches on the id or a word, then a word that starts with the query, then partial matches. Among exact matches, meaning leads: an icon tagged with the query (`trash`, tagged `delete`) comes before an icon only named for it (an icon that draws the Delete key), unless more of the searched icons are named for the query than tagged with it (`user`). `astryx icon <set>/<id>` reads one icon with every variant's import line (`icon.detail`). `astryx icon --list` lists the sets and which shared icon names each one fills (`icon.list`). `--set` and `--limit` (default 10) narrow the search.
- **`astryx search`.** Results now include installed icons under the new `icon` domain (`--type icon`). An icon ranks below a component or doc match of equal score.
- **Project icon set.** The new `iconSet` field in `astryx.config` (`"<set>"` or `"<package>/<set>"`) picks the project's set. Without it, the only installed set is used. `astryx template` (printed or copied) rewrites icon imports to the project's set. A set's data can list reviewed `matches` for icons in other sets, each with confidence `exact`, `strong`, or `likely`. Mapping uses an `exact` or `strong` match first, then a shared icon name, then the id, then shared words. A `likely` match is only suggested, and any icon with no match keeps its import. `template.show` and `template.copy` gain an `icons` report that lists each icon as `mapped` or `kept`. Printed source reports the same lines on stderr.
- **Checks.** `astryx integration check` (and `doctor integration validate`) adds these icon-set codes. Errors: `invalid_icon_set`, `icon_export_missing` (exports are read statically and re-exports followed), and `icon_theme_map_mismatch`. Warnings: `icon_source_version_drift` and `icon_license_notice_missing`. `astryx doctor` adds an `icon-sets` check. It fails when `iconSet` names a set that is not installed. It warns when two sets are installed and none is chosen, and for each withdrawn set.
